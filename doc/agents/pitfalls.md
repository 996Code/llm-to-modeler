# 惯发坑（踩过的，别再踩）

- **route() 元组漂移**：改路由返回契约时 grep 全量调用点，不是只改入口。
- **批量改必落点验证**：先读签名/调用方 → 改 → 即跑该文件测试；验证后置曾致 31 测试连锁失败。
- **后台 agent 静默失败零产出**：汇报完成前必须核实文件真实存在。
- **部署后"页面没变"三因**：后端未重启 / HMR 未刷到 iframe / 看错组件。
- **psql 远程查询**：`created_at` 是 TEXT，比较要 `::timestamptz`；表在 knowledge_graph schema 要带前缀。
- **SSH 远端多命令输出拼接**（无尾换行）：用 `grep -o + cut` 提取单值，别依赖行号。
- **zsh glob**：`--include=*.ts` 要引号；`==` 在 zsh 是保留词。
- **zsh 只读变量**：`status` 不能当变量名。
- **starlette/httpx2**：跑测试必须用 backend/.venv（uv），旧 venv 收集期就报错。
- **导入运行中不部署**（守卫会拦）：FORCE_DEPLOY 仅限 LLM 抽取期；向量写入期并发构建会压垮宿主机（10-19 负载 338 事故）。
- **rsync --delete 带上工作区在途文件**：部署必须从干净 worktree 出包（10-26 定型）。
- **大文件导入 OOM**：原始字节全程持有 + bge-m3 叠加顶爆 2g cgroup；现行代码解析完即 del data。
- **测试数据认账**：归因给用户前先查数据归属（可能是自己实测造的）。
- **改了配置"没生效"**：先查是 DB 值还是 yaml 出厂默认（维护在数据库 = 写 DB 值不改 yaml）。
- **测试库一律用常驻 chatbi-postgres 新建库（用户裁定 2026-10-28）**：不另起容器/实例；新库必须先 `CREATE EXTENSION vector` 再跑（conftest 只建库不装扩展——10-28 实录：15 个 KG 用例整片报 `type "vector" does not exist`，误判成回归）。另注意：全量出现失败先在**同一库单独重跑**失败文件区分真回归 vs 并发改码中间态。
- **uvicorn --reload 会失联**：进程跨大重构（目录/文件大改）后不再热载，表现为"源码对了、接口行为还是旧的"；验证前 `lsof -iTCP:端口` 看监听进程启动时间，可疑直接重启（10-28 实录：18080 跑了两天前的进程，dry-run 一直复现旧行为）。
