## 一、这是什么

njmind_form 是 AI 助手里负责**表单配置**的能力插件。你在聊天窗里用一句话描述需求，AI 生成符合平台规范的表单配置，并经过上游校验后交给你确认——**确认之前，你现有的表单永远不会被改动**。

| 能力 | 一句话说明 | 典型说法 |
|------|-----------|---------|
| 创建表单 | 自然语言 → 完整表单配置 | "创建一个请假表单，包含姓名、开始日期、事由" |
| 修改表单 | 在当前表单上加 / 删 / 改字段和属性 | "加一个手机号字段"、"把邮箱改成必填" |
| 查看表单 | 查看当前表单或按标识查已有表单 | "简述一下当前表单"、"查看 leave_apply 的配置" |
| 复制表单 | 基于已有表单生成副本 | "复制请假表单，名称改成年假申请表" |
| 图片生成 | 上传草图 / 截图 → 表单配置 | （上传图片）"根据这张图生成表单" |
| 字段权限脚本 | 自然语言 → 字段权限 JS 脚本 | "写段脚本让金额只有财务能编辑" |
| 过滤条件 SQL | 自然语言 → 数据过滤 WHERE 片段 | "生成过滤条件：只看本部门的数据" |
| 通用问答 | 闲聊、问 AI 能做什么 | "你能帮我做什么？" |

**核心安全承诺：AI 永不落库。** 所有工具的产出都是"候选配置"，只存在于对话中；只有你点了卡片上的「应用」，配置才会写回设计器画布，而画布的最终保存仍由你在设计器里操作。全程 AI 不直接写数据库。

## 二、使用前提

1. **平台已接入**：你使用的设计器页面已部署并接入 AI 助手服务。服务未部署或不可用时，AI 入口（悬浮球 / 按钮）会自动隐藏，不会出现"点了没反应"。
2. **已登录设计器**：AI 调用平台接口时沿用你的登录态。登录态过期时 AI 会明确提示（见 [FAQ](#十常见问题faq)），刷新页面重新打开即可。
3. **（独立部署场景）** 如果你用的是独立页面而非嵌入式悬浮球，需要管理员提供访问地址；上游平台地址由宿主系统按请求下发，无需你手工配置。

## 三、界面导览

### 3.1 嵌入模式（设计器内，最常用）

- 设计器页面**右下角悬浮球**，点击展开聊天窗口；窗口打开时悬浮球隐藏，关闭窗口（✕）后悬浮球回来。
- 窗口**保活**：关闭只是隐藏，重新打开会继续上次的会话，上下文不丢。
- 窗口右上角两个按钮：
  - **➕ 新对话**：清空当前对话回到欢迎页。想换一个表单从头开始时用它（生成过程中不可点）。
  - **✕ 关闭**：收起窗口。
- 每次发消息前，AI 会自动读取**设计器画布上的当前表单**作为工作基线——你不需要手动"告诉"它现在编辑的是哪张表单。
- 点「查看 JSON」全屏对比时，窗口会临时撑大到近全屏，关闭对比后恢复。

### 3.2 独立模式（独立访问地址）

三栏布局：左侧会话列表、中间聊天、右侧 JSON 预览。功能与嵌入模式一致，区别是修改基线来自会话内最近一次生成的配置，而不是设计器画布。

### 3.3 聊天输入框

- 文本框：输入自然语言需求。
- **📎 附件按钮**：上传图片（手绘草图、纸质表单照片、其他系统截图），用于图片生成表单。
- 发送后底部出现**实时进度条**（如"获取指南 → 解析字段 → 生成配置 → 校验结果"），每一步完成会打勾，你能随时看到 AI 正在干什么。

### 3.4 欢迎页

新对话的欢迎页有**示例卡片**（如"请假申请表"、"联系人表"、"客户反馈表"），点击即自动填入对应的示例指令，改几个字就能用——第一次上手建议从示例卡开始。

## 四、快速上手：三个典型场景

### 场景 1：一句话创建请假表

1. 点开 AI 窗口，输入：
   > 创建一个请假申请表，包含姓名、部门、开始日期、结束日期、请假类型（事假/病假/年假）、请假事由，姓名和日期必填
2. AI 解析需求 → 匹配字段模板 → 生成配置 → 提交平台校验，进度条依次点亮。
3. 完成后收到一张**配置卡片**，摘要形如：`已生成「请假申请表」，共 6 个字段`。
4. 点「查看 JSON」检查改动明细，满意后点「应用」写回设计器画布，最后在设计器里保存。

如果只说"创建一个表单"而没有任何名称或字段信息，AI 会**先追问**（例如"请补充表单名称或需要哪些字段"），回答后自动继续，不会瞎猜。

### 场景 2：在当前表单上加字段

1. 在设计器中打开一张表单（画布上已有内容），打开 AI 窗口：
   > 加一个手机号字段，非必填；再把部门改成必填
2. AI 以画布上的表单为基线做**增量修改**，进度条：获取指南 → 规划指令 → 应用修改 → 校验结果。
3. 完成摘要形如：`已修改「请假申请表」，共 7 个字段（加了 手机号；部门改为必填）`——括号里列出实际应用的改动，改了什么一目了然。
4. 确认无误点「应用」，画布更新。

> 只提你要改的，其余字段**原样保留**——AI 被明确约束"用户没提到的一律不碰"。

### 场景 3：上传图片生成表单

1. 点 📎 上传一张表单草图 / 截图（可附一句话说明，也可不写）。
2. AI 识别图中的字段标题、控件样式、必填标记，生成对应配置并校验。
3. 识别结果不满意？继续用修改指令调整，例如"把第 3 个字段改成下拉选择，选项是 A/B/C"。

## 五、功能详解

### 5.1 创建表单（create_form）

**什么时候触发**：你指名要一个**新表单**——"创建 / 生成 / 做一个 XX 表单"，无论当前画布上有没有内容。

**过程（进度条 6 步）**：

```
获取指南 → 加载模板 → 解析字段 → 匹配模板 → 生成配置 → 校验结果
```

- **获取指南 / 加载模板 / 匹配模板**：AI 从平台拉取官方字段类型表和配置模板，保证产出结构符合平台规范——不是自由发挥。
- **解析字段**：把你的自然语言拆成结构化字段清单。信息不足时**暂停追问**，你回答后从中断处继续。
- **生成配置**：按模板组装完整配置。
- **校验结果**：提交平台校验接口。不通过时 AI 会带着错误自动修复重试（最多 3 次）；最终仍不通过会**如实告知**（"生成后未通过上游校验（共 N 处）…"），不会谎报"已生成"。

**需求怎么写**（详见[第九节](#九指令技巧与最佳实践)）：字段名 + 类型 + 选项 + 必填。说清楚类型和选项的效果最好；只给字段名时 AI 会按常识推断（手机号 → 文本而非数字、部门 → 部门选择、审批人 → 人员选择）。

### 5.2 修改表单（modify_form）

**什么时候触发**：画布（或会话内）已有表单，你对**这张表单**提出加 / 删 / 改的要求。

**能改什么**（常用的都覆盖）：

| 你想改的 | 示例说法 |
|---------|---------|
| 字段属性 | "把手机号改成必填"、"邮箱字段改名为联系邮箱"、"备注改成多选" |
| 新增字段 | "加一个紧急联系人字段"、"在日期后面加一个附件字段" |
| 删除字段 | "删掉备注字段" |
| 表单属性 | "改成两列布局" |
| 按钮文案 | "提交按钮改名叫'保存'" |
| 选项内容 | "请假类型加一个'调休'选项" |
| 大重构 | "所有字段重新分组"（AI 自动切换到全量重生成模式） |

**为什么修改很快**：默认走**增量模式**——AI 只输出"操作指令集"（加什么、删什么、改什么），由系统确定性地应用到现有配置上，通常几秒完成；只有当指令表达不了（大重构）或多次定位失败时，才自动升级为全量重新生成（进度条会提示"修改较复杂，正在全量重新生成配置…"）。

**修改的保护规则**：

- **只动你提到的**：未提及的字段逐字节保留，改 A 不会误伤 B。
- **已有字段的数据库标识不被改名**：字段标题可以随意改，但字段在数据库中的唯一标识（fieldTitleKey）与已存数据的关联会被保护，不会出现"改个名、历史数据全错位"的事故。
- **差分校验**：校验只对**本次修改新引入的问题**负责。如果原表单本来就有历史遗留的校验警告，AI 不会因此反复重试（也修不动平台存量问题），只要"没有变得更糟"即视为通过。

**空画布不能修改**：画布上没有表单时，"改一下"类指令不会（也不该）被当成修改执行——AI 会从创建、查询、图片生成等合法选项里理解你的意图。

### 5.3 查看表单（get_form）

两种用法：

- **问当前表单**（最常用）："简述一下当前表单"、"这个表单里都有什么字段？"——AI 直接读取画布上的配置回答，列出字段清单。
- **按标识查已有表单**："查看 leave_apply 的配置"——AI 从你的话里提取表单标识（英文 / 拼音编码，如 `qingjia_sqb`）并调平台接口查询。只说中文名（如"请假表单"）时 AI 会尝试推断标识，推断不出会请你补充。

查询是只读操作，不改动任何数据。

### 5.4 复制表单（clone_form）

**说法**："复制请假表单"、"基于 qingjia_sqb 创建一个副本，名称叫年假申请表"。

规则：

- 你**没指定**新名称 / 新标识时，自动生成：名称加后缀"（副本）"，标识加后缀 `_copy`；
- 你**指定了**（如上例），按你说的来；
- 复制产物同样经过平台校验，同样以候选配置交付（点「应用」才生效），不直接落库。

### 5.5 图片生成表单（image_form）

上传图片（草图 / 照片 / 截图）后让 AI 生成表单。识别逻辑：

- 从图中的**文字**推断字段标题，从**控件样式**推断类型（出现"男/女"→单选、日期控件→日期、多个并列选项→下拉 / 多选）；
- 带 `*` 星号标记的字段推断为必填；
- 表单名称从图片标题或内容推断。

注意：图片识别对常见控件推断较准；复杂控件识别错类型时，生成后用一条修改指令纠正即可（"把这个字段改成人员选择"）。校验未通过时 AI 会返回配置并明确标注校验失败原因，供你决定是否继续调整。

### 5.6 通用问答（chat）

打招呼、闲聊、问"你是谁 / 你能做什么"——AI 会自动介绍当前系统接入的全部能力（能力清单是动态的，新插件上线后无需更新话术）。与表单无关的问题也会得到友好回应，不会硬扯到表单上。

> 平台接入的能力插件（pack）在持续增加：除本手册讲的 njmind_form（表单配置 AI）外，还有 njmind_list（列表页配置 AI——在列表设计器里用自然语言生成/重造列表的列、筛选、按钮与数据过滤）、njmind_bpm（流程配置 AI——在流程设计器里用自然语言生成/重造审批流程与规则）等。在哪个设计器页面打开 AI，就自动使用该页面对应的能力。

### 5.7 字段权限脚本（generate_js_script）

用自然语言生成"谁在什么场景下能看 / 能改某个字段"的 JS 规则脚本。脚本位共 5 个：

| 脚本位 | 含义 |
|--------|------|
| editFieldCode | 可编辑 |
| showFieldAddCode | 新增时可见 |
| showFieldDetailCode | 查看时可见 |
| viewDetailCode / editDetailCode | 子表明细的"可查看 / 可编辑已有行"两码（针对子表单字段本体） |

除字段权限 5 个脚本位外，还支持 **12 个扩展 Profile**（`script_profile` 参数显式指定），合计 **17 种配置位**：

| 场景 | Profile |
|------|---------|
| 表单（form） | 字段值变化事件、字段外链 |
| 按钮（button） | 前置 / 后置 / 隐藏条件 / 禁用条件 / 跳转链接 / 自定义事件 |
| 列表（list） | 列表链接、列表格式化、列表字段隐藏条件、列表自定义渲染 |

其中"外链 / 跳转链接 / 列表链接"三个 URL 类 Profile 有**可执行链接门禁**：产物必须包含可执行的 URL 或基于字段值的动态拼接规则，否则校验不过、重试后丢弃。"列表自定义渲染"用于整列单元格的自定义渲染脚本（如按状态值渲染不同样式）。

**两种入口**：

- **弹框场景**（字段设置里点 AI）：设计器会把目标字段、脚本位等参数随请求显式下发，并在消息头带 `[script:js]` 标记——AI 直接定位目标，不猜。校验失败会带原因自动修正重试（**最多 2 次**，注意与表单生成的 3 次重试是两套机制）；仍不通过就**如实丢弃**，明确告知"脚本生成未完成（校验未通过）"，绝不把残缺脚本当成品交付。
- **悬浮窗场景**：没有显式参数时，用自然语言描述需求（如"写段脚本让金额只有财务能编辑"），AI 结合画布字段目录由 LLM 定位字段与脚本位，定位不到会追问。

脚本必须符合平台契约（函数表达式、返回 `false` 才拦截），生成前会做结构校验与字段引用反查——引用了表单里不存在的字段会被拦下重修。

### 5.8 过滤条件 SQL（generate_filter_sql）

用自然语言生成数据过滤的 WHERE 片段，覆盖 4 个配置位：引用记录过滤、关联数据过滤、列表数据权限、列表默认过滤。

生成结果经过多层防御性校验：

- **列名白名单**：只允许使用上下文字段目录和系统列（系统列按主表 / 子表场景分流），写不存在的列会被拦下；
- **宏白名单**：只允许 `njmd_*` 平台宏（如部门范围、流程实例判断），且依赖流程列的宏在子表场景禁用；
- **三库方言黑名单**：兼容 Oracle / MySQL / DM8，禁用 `to_date`、`nvl`、`||` 等专有函数与写法，只允许 ANSI 标准写法；
- 同 5.7：弹框场景带 `[script:sql]` 标记确定性直达，校验失败重试最多 2 次后如实丢弃。

**时间条件怎么写（当年 / 去年 / 近 N 年 / 当月）**：说"当年、去年、近3年"这类**相对时间**时，AI 生成的是动态写法，不写死年份——例如"当年"产出 `EXTRACT(YEAR FROM 字段) = EXTRACT(YEAR FROM CURRENT_TIMESTAMP)`，"去年"在右侧 `- 1`，"近3年"写成 `EXTRACT(YEAR FROM 字段) >= EXTRACT(YEAR FROM CURRENT_TIMESTAMP) - 2`，明年跨年过滤条件也不会失效；"当月 / 近 N 月"同理用 `EXTRACT(MONTH FROM ...)`（"当月"是年份与月份两个条件同时成立）。**只有你明确说了具体年份（如"2024年的数据"）**，SQL 里才会出现年份字面量。这条不只是提示词约定：校验环节会拦截"需求里是相对年份、生成的 SQL 却硬编码年份"的产物并要求重修。

## 六、看懂 AI 的产出：配置卡片与版本

每次生成 / 修改 / 复制成功，聊天流里会出现一张**配置卡片**，附带三个动作（以管理员实际开通为准）：

| 动作 | 作用 |
|------|------|
| **查看 JSON** | 全屏打开 GitLab 风格的**对比视图**（红=删除、绿=新增，附 +N −M 统计），基线是画布当前配置或上一版本；也可一键切换"完整视图"看整份 JSON |
| **应用** | 把这份配置写回设计器画布（嵌入模式下由宿主渲染，不落库）。画布的最终保存仍由你在设计器里操作 |
| **切换到此版本** | **版本回滚**，见下文 |

**校验状态**：卡片摘要会如实反映校验结论——"校验通过 ✓"才代表可直接应用；有警告时会标注警告数；未通过时会列出问题，此时建议继续对话让 AI 修复。

### 版本管理：像 git 一样回滚

- 对话里**每张配置卡片就是一个版本锚点**，没有独立的版本库页面。
- 任何**非当前版本**的卡片上都可点「切换到此版本」：当前配置立即恢复为该版本，并在「查看 JSON」里能看到这次切换的改动明细；嵌入模式下自动渲染回画布。
- **对话记录始终保留**——"反悔想用最新的"就到最新那张卡上点同一个按钮，版本之间可以互相跳。
- 切换后继续对话，修改基于切换后的版本进行。

## 七、修改还是新建？怎么说 AI 才不会理解错

这是最容易混淆、也最值得花一分钟搞清楚的规则：

| 你说的话 | AI 的理解 | 结果 |
|---------|----------|------|
| "加一个手机号字段"、"把 XX 改成必填"（针对现有表单） | **修改**当前表单 | 现有字段全部保留，只做增量改动 |
| "创建一个出差申请表"（即使画布上正开着别的表单） | **新建**一个独立表单 | 你当前打开的表单**不受影响**——新表单是独立候选，要不要覆盖由你点「应用」时自己决定 |
| "删掉重来，做一个全新的报名表" | **新建**（"重来/做一个新的"是创造性话术） | 不会在旧表单上打补丁，产出干净的新表单 |
| "识别这张图片生成表单"（空画布） | 图片生成 | 不会被误判成"创建"或"修改" |

经验法则：

- 想**改现在的** → 用"加 / 删 / 改 / 把 XX 设为 XX"这类动词，指名现有字段；
- 想**要新的** → 明确用"创建 / 生成 / 做一个 XX 表单"，并说出新表单的主题；
- 拿不准时说完整一点，AI 宁可追问也不会猜。

另外，AI 对你的意图把握不足时（路由自评置信度低于 0.6）也不会硬猜——引擎会挂起执行，先发一张"确认意图"的追问卡片，你确认目标或换个说法后再继续。

## 八、支持的字段类型

AI 生成 / 修改时使用的常用类型（以平台配置指南为准，平台新增类型自动可用）：

| 类型 | 适用场景 | 你这样说 |
|------|---------|---------|
| 单行文本 | 姓名、手机号、邮箱、地址、编号、身份证 | "姓名（文本）" |
| 数字 | 金额、数量、年龄、百分比、时长 | "金额" |
| 日期 | 日期、时间 | "开始日期" |
| 附件 | 附件、文件、图片上传 | "凭证截图" |
| 下拉选择（单选） | 需要提供选项列表的单选 | "请假类型（事假/病假/年假）" |
| 多选 | 标签、多选场景 | "兴趣爱好（多选）" |
| 部门选择 | 部门 | "所属部门" |
| 人员选择 | 人员、审批人、负责人 | "审批人" |
| 自动编号 | 流水号、自动编号 | "单号（自动编号）" |
| 子表单 / 明细表 | 一对多明细行 | "明细（每行包含物品名称和数量）" |
| 分组 | 字段分区、分隔 | "把基本信息分为一组" |
| 富文本 | 富内容、长文本 | "详细说明（富文本）" |
| 关联数据 / 引用记录 | 关联其他表单数据 | "关联客户档案" |

**暂不支持 AI 生成**的类型：条码、标签页、文本段、签名。你的描述里涉及这些时，AI 会明确提示"字段类型「XX」暂不支持 AI 生成，请改用文本/数字/单选等基础类型"，**不会**静默用文本类型顶替。建议先用基础类型生成，再到设计器里手工换成这些特殊类型。

## 九、指令技巧与最佳实践

1. **一次说全，减少往返**：字段名 + 类型 + 选项 + 必填一起给。
   - 一般："做个反馈表"
   - 更好："创建客户反馈表：客户名称（必填）、反馈类型（下拉：产品质量/服务态度/其他）、详细描述（多行）、联系电话"
2. **选项类字段必须给选项**：下拉 / 多选如果不给选项，AI 可能追问或推断出不合适的默认值。
3. **改字段用字段名精确定位**："把**请假类型**改成必填"优于"把第一个字段改成必填"——描述性指代 AI 也能理解，但点名最稳。
4. **复杂改动拆成多轮**：一次改三五处以内效果最好；大重构（"所有字段重新分组"）会自动走全量模式，耗时稍长属正常。
5. **利用对话历史**：可以连续下指令——"再加一个字段"、"刚才那个改成非必填"——AI 记得上下文（长对话会自动压缩，表单名 / 字段 / 配置结果等关键信息会被保留）。
6. **善用「查看 JSON」对比**：每次应用前扫一眼红绿对比，几秒钟确认 AI 没有动不该动的东西。
7. **不满意就回滚**：点任意历史卡片的「切换到此版本」，再继续调整，不用从头再来。

## 十、常见问题（FAQ）

**Q1：提示"获取上游配置指南失败（可能登录态过期或服务不可用），请刷新设计器页面后重新打开 AI 助手再试"？**
登录态过期是最常见原因。按提示刷新设计器页面、重新打开 AI 助手即可；若反复出现，联系管理员检查平台服务是否正常。

**Q2：AI 生成的表单直接保存到数据库了吗？**
没有。所有产出都是候选配置，点「应用」才写回画布，画布保存仍由你操作——AI 全程不碰数据库。

**Q3：我说"生成 XX 表单"时画布上正开着别的表单，会被覆盖吗？**
不会。新表单是独立候选，应用之前你现有表单无恙；点「应用」时的覆盖也是你自己的决定。

**Q4：为什么修改比创建快很多？**
修改默认走增量模式：AI 只输出几十到几百字节的操作指令，由系统确定性合并到现有配置上，通常几秒完成；创建要从零组装完整配置。

**Q5：进度条提示"修改较复杂，正在全量重新生成配置…"是什么？**
你的指令超出了增量指令的表达范围（如整体重新分组），AI 自动升级为全量重新生成，耗时略长，结果同样经过校验。同一会话内一旦升级，后续修改都走全量，保证稳定。

**Q6：校验失败怎么办？**
AI 会自动带错误修复重试（最多 3 次）。仍未通过时会如实列出问题（"生成后未通过上游校验（共 N 处）：…"），你可以继续对话让它修，或换一种描述重试。

**Q7：为什么修改后有些校验警告还在？**
修改采用差分校验：原表单**本来就存在**的历史遗留警告不由 AI 负责（也无法由 AI 修复平台存量问题）；只要本次修改没有引入新问题，即视为通过。确需处理存量问题请联系表单管理员。

**Q8：AI 把字段类型识别错了（比如把手机号设成了数字）？**
继续下指令纠正："把手机号字段改成文本类型"。创建时也可以预防——写明"手机号（文本）"。

**Q9：怎么让 AI 一次只改我说的字段？**
默认就是这样——AI 被约束"用户没提到的一律不碰"。如果发现误伤（理论上不应发生），用版本回滚到上一张卡片。

**Q10：AI 能理解拼音或英文的表单标识吗？**
能。查询 / 复制时可以直接说标识（如 `leave_apply`）；只说中文名时 AI 会尝试推断，推断不出会追问。

**Q11：新对话和继续当前对话怎么选？**
同一张表单的连续调整用当前对话（上下文有用）；换一个不相关的新表单建议点 ➕ 新对话，避免历史干扰。

**Q12：图片识别支持什么图？**
手绘草图、纸质表单照片、其他系统的表单截图都可以。字段越清晰、越接近标准表单版式，识别越准。

### 术语表

| 术语 | 含义 |
|------|------|
| 画布 | 设计器中正在编辑的表单；嵌入模式下 AI 每次干活前自动读取它作为基线 |
| 表单标识（formCode） | 表单的唯一英文/拼音编码（如 `qingjia_sqb`），与数据库关联；已有字段的标识受保护不可改 |
| 字段标识（fieldTitleKey） | 字段在数据库中的唯一标识，改字段标题不会动它，历史数据安全 |
| 候选配置 | AI 产出、尚未应用的表单配置；点「应用」才生效 |
| 配置卡片 | 聊天流中承载候选配置的卡片，附「查看 JSON / 应用 / 切换到此版本」动作 |
| 增量修改 | AI 只输出操作指令、系统确定性合并的快速修改模式 |
| 全量重生成 | AI 重新输出完整配置的模式，用于大重构或增量失败时的兜底 |
| 追问 | 信息不足时 AI 挂起等待你补充，回答后从中断处继续 |
| 校验 | 把配置提交平台校验接口检查规范性；通过才建议应用 |
