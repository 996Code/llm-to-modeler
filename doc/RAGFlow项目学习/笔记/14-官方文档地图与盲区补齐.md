## 2. 前端全面深读（C 轮，补齐 B 轮）

### 2.1 状态管理
- 客户端状态 zustand，**全仓仅两个 store**：useGraphStore（画布，devtools+immer）+ useChatStreamStore（SSE 流模块级单例，跨路由存活+会话 LRU 淘汰）
- 服务端状态全走 react-query v5：30+ 个 use-*-request.ts 按域拆文件；queryKey **枚举工厂双轨**（新式层级化 DocumentKeys.all/list 便于 invalidate，旧式裸数组并存）；mutation 后统一 invalidateQueries；chunk 创建延迟 1s 再失效

### 2.2 画布编辑器
- @xyflow/react v12 注册 **27 种 nodeTypes**（emailNode 已注释）+单一 ButtonEdge；连线校验四规则（禁自连/RestrictedUpstreamMap 上游限制/父子容器一致/DFS 环检测）
- 表单 react-hook-form watch 实时回写 store（immer 冻结态深拷贝防变异报错）；**DSL 转换集中在 dsl-bridge.ts**（dslToGraph/graphToDsl/importDsl/exportDsl），执行拓扑从 graph 重建 components 后端只读
- 单步调试：Begin 参数动态生成 zod schema（string/bool/int/file/object 分支）

### 2.3 数据集管理页
- **无虚拟滚动**：react-table+URL 同步分页；chunk 编辑表单（content/image_id/available/tag 数组）保存后 message.success+延迟 invalidate，无显式"重嵌中"反馈
- **条件式轮询**（最值得抄）：refetchInterval 函数式——仅 has_active_tasks 或有 processing 文档时 5000ms，否则停；搜索 useDebounce 500ms 才进 queryKey

### 2.4 API 客户端层
- 双客户端并存过渡：umi-request（@deprecated）→ axios（next-request）；URL 集中字典 api.ts
- 拦截器统一：camel↔snake 键转换、Authorization 注入、tenant 附加；响应统一弹错（401 去重后清凭证跳登录）
- **SSE 不走 axios**：原生 fetch（拿 ReadableStream）+ eventsource-parser 的 EventSourceParserStream 手动 reader 循环，鉴权头手动注入，AbortSignal 调用方传入

### 2.5 i18n 与主题
- i18next 17 种语言，仅 en 同步打包，其余**动态 import 懒加载**；单 namespace 顶层 33 域（flow 最大 1100+ 行，en.ts 共 3987 行）
- 暗色自研 Context Provider+localStorage+documentElement class；tailwind darkMode:['selector']+CSS 变量全映射；分享页 URL 临时换肤（useSyncThemeFromParams）

### 2.6 工程化
- 路由集中 routes.tsx（90+ 路径+lazy+Suspense）；**root loader 支持 ?auth= 参数写 token 后重定向**（嵌入场景鉴权传递！）；admin 子树按 IS_ENTERPRISE 条件展开
- 分层严格：pages/components/hooks/services/utils/interfaces/constants；68 个测试文件（Jest+jsdom+自研 esbuild transformer）；Vite 7+oxlint/oxfmt；dev 挂 why-did-you-render

## 3. Go 主干 ingestion 与 syncer（C 轮）

### 3.1 ingestion 管线
- **Pipeline=编译后的 canvas+任务元数据**（ingestion/pipeline/pipeline.go:36-45，从 DSL 编译执行）——"解析也走画布运行时"在 Go 版是字面实现；12 内置模板 go:embed
- 组件经 runtime.MustRegister（CategoryIngestion）；chunker→Tokenizer（内嵌 embedder，绑定 KB embd_id）→index_writer 靠 DSL 边衔接；**chunk 分批写、非末批 no-refresh**（省 refresh 开销）
- 进度上报更精细：ProgressSink 事件 → 内存高水位 + **1s 定时合批刷库**（对照 Python 的每次写）

### 3.2 解析能力
- PDF 完全平移（渲染/OCR/DLA 版面/TSR 表格），**PDFium 静态链接+全进程互斥**；ONNX 用 fork 的 onnxruntime_go（CGO+libonnxruntime.a 静态进二进制、dlopen(NULL) 取符号），模型转 .ort+共享权重缓存+会话池
- tcadp/docling/mineru 远端解析适配同存；42 连接器**全量平移且超 Python 版数量**

### 3.3 NATS 任务调度（对照 Redis Streams）
- 流 RAGFLOW_TASKS：WorkQueue+DiscardNew、1M 条/1GB 上限；消费者 AckExplicit/MaxDeliver 16/AckWait 60s/BackOff 5-15-30-60s
- **无死信队列**（超 16 次即丢，靠 DB 状态重试）；**发布端故意不做 MsgID 去重**——防重靠消费侧 CREATED/SCHEDULED→RUNNING CAS+进程内 claim 集合；心跳 InProgress 2s 必须小于 BackOff[0]（心跳/退避时序约束！）
- syncer 独立流+durable push consumer+DeliverGroup 竞争消费；Duplicates 窗口 10min

### 3.4 syncer 断点
- checkpoint 存 **JetStream KV 桶**（TTL 7 天），降级内存实现；断点含窗口/游标/重启计数；ErrSyncResumeInvalid 触发**锚点重启**（受 MaxAnchorRestartCount 限制）；完成即删
- prune=全量 slim 快照→retain 集合→DeleteStale；Redis 分布式 ConnectorLock+公平批执行器

### 3.5 双版本并存真相
- **运行时已无 Python**：entrypoint 只拉 Go 单二进制四模式（--api/--syncer/--ingestor/--admin）；Python 仅剩三类资产——rag/prompts 49 个 md（Go main 口径；Python v0.27.2 为 47，Go 运行时读）、tools/ 工具脚本、测试工具链
- **重写值不值**：进度/防重/断点语义都比 Python 精细，代价是 ONNX/PDFium 全静态 CGO 构建链复杂（build.sh 大量 ORT 种子逻辑）

### 4.2 MCP server 深读（mcp/server/server.py，935 行）

- **ragflow_retrieval**：入参 11 项（question 必填/dataset_ids/similarity_threshold 0.2/vector_weight 0.3/rerank_id/force_refresh 等）；透传 /retrieval 十项；返回 chunks+分页（total_pages 整除向上）+query_info
- **双层元数据缓存**（为何 retrieval 前拉元数据的答案）：/retrieval 的 chunk 只带贫字段（document_keyword/dataset_id），必须先逐库拉 dataset+document 元数据才能补文档名/类型/大小——进程内 OrderedDict **LRU 32 条+TTL 300s±30s 随机（防雪崩）**，惰性过期+force_refresh 跳过，异常优雅降级空缓存
- **_map_chunk_fields**：保留原始字段+三个增强（dataset_name 查缓存/document_name 别名/整份 document_metadata 挂载）
- **鉴权两模式**：self-host 全局 HOST_API_KEY（单租户）；host 模式 AuthMiddleware 每请求 Bearer/x-api-key 提取→scope.state→with_api_key 透传——**租户路由完全由每请求 token 决定，服务端无会话**
- **无流式**：retrieval 一次性 JSON；SSE/streamable-http 只是 MCP 协议通道不影响工具语义

**对我们 MCP 出口（终局项）的直接映射**：三工具克制形态已验证正确；元数据缓存模式（LRU+随机 TTL 防雪崩+force_refresh 逃生口）照抄；每请求 token 无会话路由与我们 X-User-Id 透传天然同构。
