09 · 评测、可观测与性能

测试体系、离线基准、在线反馈、Langfuse 集成与性能治理。

1. 测试体系

  • run_tests.py:113-238 只跑 test/unit_test（coverage/xdist）；Go 入口 run_go_tests.sh
  • API/SDK 集成测试需完整 Docker 栈（MySQL/Redis/MinIO/ES/Infinity/TEI）+ 真实 LLM Key（test/README.md:31-97）
  • Playwright E2E：登录/数据集上传解析/Chat/Search/Agent（test/playwright/）
  • CI 只跑 unit+API/SDK，未纳入 Playwright/独立 integration（.github/workflows/sep-tests.yml:362-368）

2. 离线评测基准（rag/benchmark.py）

  • Benchmark 类：ms_marco_v1.1（:87）/ trivia_qa（:123）/ miracl 18 语言（:157）
  • 流程：读 parquet/TSV 构建 qrels（query→chunk_id→相关性分）→ embedding 建索引 → retrieval 取 top30（similarity 作 run 分）
  • 指标用 ranx：ndcg@10 / map@5 / mrr@10（:231-259）
  • 逐 query 排序写 result.md（:206-223）——坏例定位；qrels/run 落盘 JSON
  • 数据自备 HF 链接，无下载脚本

3. 性能压测（test/benchmark/）

  • 独立 CLI 包两场景：chat（SSE 记 t0/首token t1/结束 t2）与 retrieval（延迟）
  • p50/p90/p95 最近邻法（metrics.py:41-67）；QPS=请求/总时长（report.py:22-25）
  • ProcessPoolExecutor(spawn) 并发（cli.py:407-409）；可自动建库/传文档/等解析；一键脚本 run_retrieval.sh

4. 在线可观测

  • 日志：控制台+10MB×5 滚动文件，动态调级（common/log_utils.py:27-85）
  • OTel/Jaeger：默认关闭，Go 有 span hook 但 provider 初始化仍空壳（conf/service_conf.yaml:62-68）
  • Langfuse：租户级三键配置（langfuse_api.py:26-58）；埋点仅单条 generation observation（name="chat"，含 prompt/messages/usage，dialog_service.py:944-957）；检索不单独埋；失败静默降级——粒度比我们 call_logs 粗
  • stats API：PV/UV/token/速度（stats_api.py:24-49）
  • 任务心跳：pending/lag/done/failed/current（task_executor.py:1870-1948）
  • token/耗时留痕，无统一费用落库

5. 性能治理

  • 默认任务并发 5、解析/embedding 并发 1（task_executor_limiter.py:20-28）；embedding 批 16、索引批 32
  • Redis 缓存 LLM/embedding 24h（graphrag/utils.py:170-211）
  • 知识编译池：max_pending 背压、按模型自适应降并发、指数退避（structure.py:292-353）
  • worker 按任务数回收防 ONNX/GPU 内存碎片
  • v0.25.5 高峰：ES 检索延迟-50~100%（去多余向量取回）、启动-5~9s（懒加载 import）、元数据过滤下推

6. 恢复能力

  • 重启消费同名 consumer 的 unacked；任务最多 3 次（redis_conn.py:456-475）
  • 取消：Redis 标记+同步 DB 状态
  • 缺口：无 XAUTOCLAIM 僵尸抢占、requeue_msg 无调用、跨 worker pending 可能滞留；索引批写后存 chunk IDs，任务消失回删——但源码承认仍有最终写竞态，无通用巡检修复

对我们的启示

  • ChatBI 评测集照抄形态：evalset.json{query,expected_tables,expected_sql,difficulty} + ranx recall@k/MRR + SQL 比对执行结果集（容错列序） + p50/p90 模板 + per-query 坏例报告
  • 我们 call_logs 的逐环节 stage 观测领先 RAGFlow（他们 Langfuse 只到 generation 级）——保持
  • 背压+自适应降并发+指数退避三件套：KG 导入熔断已有等价物，编译通道扩展时参照
