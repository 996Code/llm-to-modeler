10 · 安全与沙箱

认证授权、文件防护、Agent 沙箱与密钥治理——事实与风险分开列，风险项即我们的避坑清单。

1. 认证链

事实：login_required（api/apps/init.py:235）依次尝试 session cookie（Redis 存储）→ Bearer → itsdangerous JWT → APIToken 表 → BETA token（:144-213）；密码 werkzeug 哈希；登录口令 RSA 解密；OAuth2/OIDC/GitHub 带 state CSRF 校验。

风险：CORS allow_origin="*"（:62）与 Bearer/API-key 共存——任意源可读 API 响应；登录失败区分"邮箱未注册"可枚举用户；RSA 私钥口令硬编码"Welcome"（utils/crypt.py:39）。

2. 授权边界

事实：三层防护（API 装饰器 → service accessible() → SQL where tenant_id）；角色四档 OWNER/ADMIN/NORMAL/INVITE。

风险：accessible 分散各 service，新端点漏加即越权；ADMIN 语义不完整。

3. 文件与输入防护

事实：上传无扩展名/MIME 黑白名单，仅数量限制+全局 1GB；folder 名禁"/"；SSRF 有专门模块 common/ssrf_guard.py（assert_url_is_safe、DNS pinning 防 rebinding、IPv4-mapped IPv6 归一化）——web/sitemap/rss/rest_api connector 全走它。

风险：无类型校验，恶意文档依赖解析器自身加固；SSRF 有环境变量旁路，误配即失效。

4. Agent 代码沙箱

事实：executor_manager 容器化执行——gVisor（--runtime=runsc）+ --read-only + 默认 --network none + 内存 256m + 超时 10s（core/container.py:88-116）；/run API token fail-closed+限速+仅绑 loopback；AST 静态黑名单（禁 os/subprocess）；providers 含 local（明示"非沙箱边界"，门控 SANDBOX_LOCAL_ENABLED）/self_managed/e2b（30s 硬限）/aliyun。

风险：manager 自身 privileged:true + 挂 docker.sock——DinD 结构，manager 被攻破即宿主 root；AST 黑名单可被动态手段绕过，实际边界全靠 gVisor；local 模式零隔离。

5. 密钥治理

事实：TenantLLM.api_key TextField 明文列（db_models.py:1232）；AES 加密（PBKDF2 固定 salt）仅用于数据库连接密码；connector_runner 异常帧敏感键 （有回归测试）；HTTP 客户端 URL 敏感参数脱敏；service_conf 默认口令 infini_rag_flow。

风险：模型 key 明文落库，DB 泄露即全部供应商凭据泄露；固定 salt 削弱加密；默认口令未强制改。

6. Prompt Injection 面

事实：检索 chunk 以"ID/Title/Content"树形格式原文拼进 system prompt（generator.py:140-175），无消毒或包裹标记；XSS 防护在前端：DOMPurify+rehype-sanitize（答案渲染 LaTeX 预处理后再消毒防 entity 绕过）、SafeImg 拦截 onload。

风险：知识库内容可信边界缺失——恶意文档可注入指令操纵 Agent（尤其有代码执行/TLS 工具时）。

我们的避坑清单（已写入蓝图第 6 节）

  1. 模型 key 用加密列（pgcrypto）——不学明文
  2. 开放出口时 CORS 白名单——不学 *
  3. 检索内容消毒保持并扩展（我们已有 defang，retrieval.py:293-296）——不学裸拼
  4. 沙箱选 rootless/代理——不学 docker.sock 直挂
  5. 混检权重方向：向量 0.3/全文 0.7（复核修正，别信网传）
