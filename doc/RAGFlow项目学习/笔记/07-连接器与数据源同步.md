> 35+ 数据源接入、指纹增量、稳定 ID 幂等与删除对账。

## 1. 体系结构
> 🗺 对应链路图：[../图/ragflow-connector-sync.html]（bind-schedule 视图）

- **35+ 连接器**（common/data_source/）：GitHub/GitLab/Bitbucket/Azure DevOps、Google Drive/OneDrive/Dropbox/Box/SharePoint/Seafile/WebDAV、Notion/Confluence/Jira/Asana/Airtable/Salesforce/Zendesk、IMAP/Gmail/Outlook、Slack/Discord/Teams、RSS/Sitemap/REST API、MySQL/PostgreSQL/BigQuery、钉钉多维表、xquik
- 独立 data_sync 进程轮询 due 任务并发执行（sync_data_source.py:2349-2379）；Go 主干有对应 syncer（checkpoint_store 增量）
- 官方文档（docs/guides/data_source/）：首轮全量、后续按刷新间隔增量、可选删除同步

## 2. 指纹增量（防重下载/重嵌）
> 🗺 对应链路图：[../图/ragflow-connector-sync.html]（incremental 视图）

- 列表 fingerprint 与已存 content_hash 相同 → 跳过 GetObject 下载与重嵌（sync_data_source.py:395-451）
- 首同步全量、后续按 poll_range 水位增量；同步状态全量留痕 SyncLogs（docs/errors/poll_range 可审计）

## 3. 稳定文档 ID（幂等入库）
> 🗺 对应链路图：[../图/ragflow-connector-sync.html]（incremental 视图）

- doc_id = hash128(kb_id:connector_id:external_id)，重跑更新原行而非复制（connector_service.py:66-104）
- 兼容两代历史 ID 派生（≤v0.25.1 无 kb_id 的旧格式），跨库碰撞拒绝写入
- 35+ 连接器统一 SyncBase 模板：checkpoint 迭代 + 批量 yield + 迭代上限 10 万防死循环（:141,1771-1796）

## 4. 删除对账与重建
> 🗺 对应链路图：[../图/ragflow-connector-sync.html]（prune-rebuild 视图）

- 开启 sync_deleted_files 时独立 prune 任务：取远端快照比对，删除端侧孤儿（:322-367）
- rebuild：删该连接器全部文档后重新排期全量（connector_service.py:205-240）；授权在 service 层（非 HTTP 层）——删数据操作必须校验 kb 可达+连接器绑定
- 凭证安全：connector_runner 对异常帧 f_locals 敏感键替换 <redacted>（:84,254-257，有回归测试）；SSRF 防护专门模块 common/ssrf_guard.py（DNS pinning 防 rebinding）

## 5. MCP Server（mcp/server/server.py）

深读版见《14-官方文档地图与盲区补齐.md》§4.2（入参/双层缓存/字段映射/鉴权/流式全解）。要点：只开 3 工具（retrieval/list_datasets/list_chats）克制形态；元数据 LRU+随机 TTL 防雪崩；每请求 token 无会话路由。

## 对我们的启示

- 宿主数据源接入（终局项）走 AssetClient 契约 + pack 任务框架，**fingerprint 增量模式直接照抄**（我们 KG 已有 content_hash 查重，天然对齐）
- 稳定 ID 三元组（kb:connector:external_id）防跨库碰撞的思路可用于 KG 文档 ID
- MCP 出口（终局项）照抄"3 工具+元数据缓存+REST 代理"的克制形态，不贪多
