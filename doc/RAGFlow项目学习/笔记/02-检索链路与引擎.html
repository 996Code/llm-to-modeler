1. 三段式检索链

🗺 对应链路图：[../图/ragflow-chat-retrieval.html]（query-prep 视图）

问句准备（检索之前）： - full_question 多轮合成：已完整则原样返回；相对日期锚定（注入 {{today}}/{{yesterday}}，"上个月"→绝对日期）（generator.py:256） - keyword_extraction（:226）+ cross_languages 跨语言增强（:292） - 全部发生在检索前，与检索器解耦（dialog_service.py:736-745）

混合检索： - 默认权重向量 0.3 / 全文 0.7（vector_similarity_weight，search.py:602——注意网上"向量 0.7"的说法是错的，已复核） - ES 侧取候选后本地重排（search.py:498-523）；空结果自动放宽阈值复查（min_match=0.1、sim=0.17，:272-294） - rerank 可选且启用时禁分页（:631-632）；v0.18 移除内置 rerank 模型（官方理由"对检索率影响极小但显著增加检索时间"），接口保留接外部 - KGSearch 结果作为伪块 insert(0) 与普通结果并列（dialog_service.py:783-789）

引用插入（生成之后，insert_citations）： - 代码路径：insert_citations 句级 embedding+token 混合相似度自动插 [ID:n]（search.py:316-393） - LLM 路径：独立 citation_prompt pass（见 11-Prompt工程）——两条路径并存 - chunk 携带 doc_id/kb_id/positions 坐标（:764-782）；reference 携 chunks+doc_aggs（dialog_service.py:855-894） - 前端：reference-utils.ts 匹配分组（findAllReferenceMatches/groupConsecutiveReferences）+ 轮播判定（shouldShowCarousel）+ pdf-drawer 按 positions 定位

5. 实现细节考古（第六轮）

5.1 insert_citations 句级引用算法（search.py:316-393）

  • 代码块保护：先按 `` 切分，代码块整块跳过不插引用；句界正则含中阿标点，[^|]` 前缀排除表格行；英文句尾要求"字母+标点+空白"防误切
  • 短句 <5 字符不参与；维度不匹配时 chunk 向量清零（防御）
  • 相似度：句向量×0.9 + token 相似度×0.1（引用判定几乎全靠向量）
  • 阈值递减兜底：thr 从 0.63 起 ×0.8 逐降（0.63→0.50→0.40→0.32），一旦有引用即停——保证尽量有引用
  • 警示（D 轮审查）：0.63 与 RAGFlow 默认 bge 系 cosine 分布强耦合——换嵌入模型分布整体偏移，照抄必错标，须按自有模型重标定；"有引即停"是产品兜底取舍（宁可错引不空手），非算法真理
  • 选 chunk：sim > max×0.99（最高分 99% 内都算），每句最多 4 个，全局去重（同一 chunk 全答案只标一次）

5.2 hybrid_similarity 融合公式（query.py:170-209）

  • 辨析：此为本地重排公式（cosine×0.7+token×0.3），与 §1 引擎层 vector_similarity_weight（向量 0.3/全文 0.7）是两层不同权重，方向相反——前者是检索后对候选的重排打分，后者是引擎内两路召回的融合配比
  • sim = cosine×0.7 + token_sim×0.3（检索默认）；token_sim 内部：单词 0.4 权重 + 相邻二元组 0.6 权重（隐式 bigram，中文短查询词序不丢）
  • 查询覆盖率语义：得分 = Σ(查询词在文档命中权重)/Σ(查询总权重)——只看"文档回答了问题的多少"，非对称相似度
  • D 轮审查补注：分子中文档侧权重被注释掉（s += v # * dtwt[k]）——得分只看"查询词是否出现"，与文档 token 权重无关，且无文档长度惩罚（长文档天然易得高分）；平移 PG 覆盖率公式须保持同语义，否则排序偏置
  • 向量全零时退回纯 token 相似度

5.3 词权重复合公式（term_weight.py:254-269）

  • wts = (0.3×idf_词频 + 0.7×idf_文档频率) × NER因子 × 词性因子——稀有度×命名实体加成×词性加成
  • 依赖说明（D 轮审查）：双 IDF 离不开 freq（虎切 55.6 万条）/df 两套词典——无词典时全走 OOV 兜底常量，公式退化为 NER×词性乘子；我们无词典时不可平移此公式

5.4 分词器架构（v0.27 重构后）

  • rag_tokenizer.py 仅 60 行薄封装，真身在 infinity 包（Rust/C++）——分词器跟着检索引擎走：Infinity 引擎内建分词（应用层跳过），ES 时用应用层分词
  • surname.py 573 行（中文姓氏表辅助人名识别）、delim.py 179 行（分隔符规则）

5.5 同义词双层热更新（synonym.py:34-92）

  • 本地 synonym.json 词典 + Redis kevin_synonyms key 每小时拉取（整体替换本地词典） + WordNet 兜底（纯字母词）
  • 审计注（D 轮）：覆盖语义有风险——不完整数据会砸掉线上词表；且 lookup_num<100 节流跳过刷新；PG 平移建议改合并式更新+版本号
  • PG 全文路可平移：同义词表存 PG + 定期刷新进程内缓存

5.6 LLM/嵌入缓存 key（graphrag/utils.py:170-228）

  • key = xxhash.xxh64(模型名+文本+history+genconf) 直接拼接；history 位放用途标签（"keywords"/"question"）、genconf 放 {"topn":n}——同一文本不同用途不同 key
  • 审计注（D 轮）：早期版本记录的"len≤1 截断缓存视为 miss"在源码中不存在——调用点仅判空串，勿引入多余分支
  • 嵌入向量 JSON 序列化存 Redis，批量 MGET 探 miss；TTL 24h

5.7 中文分词器全貌（虎切词典，第六轮补全）

  • 真身在 infinity-sdk wheel（556 行）；词典 huqie.txt 55.6 万条/8.3MB（词 频次 词性），加载进 datrie 双向 trie（正序+DD 逆序），缓存 54MB .trie
  • 主流程：\W+→空格→Q2B→lower→繁简→中英切分；英文 nltk+WordNet lemmatize+Snowball stem；中文正/逆向最大匹配，两结果对齐段直接采纳，分歧段 DFS 枚举全部词典切分（MAX_DEPTH=10 带 memo，连续 5+ 重复字符截断），按 30/len + ≥2字词占比 + 词频对数和 取最优
  • fine_grained：中文占比 <20% 仅按 / 拆；否则逐 token DFS 后取排序第二名的切分（比最优更细）——细粒度=次优切分，巧妙
  • NER 无模型：词性靠词典标注+ner.json 查询表（1 万条，stock 为主）+500 姓氏集合

5.8 词权重与同义词的真相

  • 词权重乘子细节：数字×2、1-2 字母×0.01、stock/corp/loca/sch×3、ns/nt 词性×3、n×2、虚词×0.3；停用词仅 31 个硬编码中文虚词
  • 同义词真相：内置 synonym.json 10,502 条几乎全是 A 股股票名↔代码——金融专用非通用库；中文 OOV 同义词无兜底
  • ES 字段权重：important_kwd^30 / question_tks^20 / title^10 / content^2——字段复制即加权（title×2/important×5/question×6 进 rerank token）

5.9 PG 全文路平移方案（六条，P2#12 实施参照）

  1. token 形态：空格分隔串，入库前已完成繁简/全半角/stem 归一化——PG 侧 to_tsvector('simple', 空格串) 即可，勿用中文 parser 重复分词
  2. 双字段→双列 tsvector：粗粒度 setweight('A')、细粒度 setweight('B')；ts_rank_cd 的交叉邻近打分天然替代 bigram×0.6 与 ~2 短语
  3. 词权重：进不了 ts_rank 就平移为字段级 setweight（title A/question B/content C），或抄 similarity() 应用层加权覆盖率公式做重排——RAGFlow 自己的重排也不依赖引擎打分
  4. 同义词：PG thesaurus 字典承接 synonym.json+热更模式；或查询侧 OR 展开降权（^0.2 模式）
  5. min_match 0.6：PG 无原生等价，用 ts_rank 阈值+查询词覆盖率替代；保留空结果降阈值两轮重试（0.6→0.1）
  6. 融合：0.3/0.7 加权+rerank 候选 64 条架构整体平移到 PG ts_rank+pgvector

5.10 前端 SSE 驱动器三模式（B 轮前端深挖，P0 参照）

  • 模块级非 Hook（run-stream.ts:1-5）：流驱动器不放组件里——页面卸载流不停，导航回来流还在跑（流生命周期独立于组件生命周期）
  • 合并式刷帧（:54-71）：chunk 到得比 UI 快，按 AnswerFlushIntervalMs 定时合并成一次 store 写入；字段 merge 而非替换——跳过 chunk 上的 reference/prompt 不丢；缓冲每次 flush 后重置
  • 错误体克隆探测（:86-90）：response.clone() 先试读 JSON——SSE 成功响应解析得 undefined，失败响应能读出错误体（流前错误检测不破坏 body）
  • 累积文本 kept local 不读回 store：免疫消息列表并发变更（mergeAnswerChunk 的 startsWith/think-marker 依赖原始累积文本）
  • 画布技术栈：@xyflow/react 12（ReactFlow），node/edge/context-menu 标准结构

5.11 引用点击与原文定位完整链路（B 轮实施参照）

标记→可点元素（markdown-content/index.tsx）： - 正则 /\[(?:ID:)?([0-9\u0660-\u0669\u06F0-\u06F9]+)\]/g（兼容阿拉伯数字，citation-utils.ts:39） - 替换形态：HoverCard + bdi 圆角胶囊（"图 N"样式），非 sup/Popover；卡片内容=chunk content（消毒后）+doc_aggs 拿 doc 名/缩略图+document_metadata；popover 不显示 similarity - 渲染管线顺序：先 DOMPurify 后 markdown——rehype 链 [rehypeRaw, RehypeSanitize, rehypeWrapReference（自定义插件把文本节点包成 custom-typography）, rehypeKatex] → 自定义 renderer renderReference 用 reactStringReplace 完成替换；插件定义在模块顶层防流式渲染重建 processor - 祛魅：reference-utils 的分组/轮播函数（groupConsecutiveReferences/shouldShowCarousel）无消费者——死代码，主路径用 reactStringReplace

原文定位（pdf-drawer）： - chunk.positions 结构：[page, x1, x2, y1, y2]（页码在 x[0]）；初值 849×1200 由 getPage(1) viewport 矫正 - 引擎：react-pdf-highlighter（非 react-pdf）——PdfLoader（pdfjs worker+鉴权头）→PdfHighlighter；滚动=scrollTo 回调+100ms setTimeout 滚到首高亮；矩形=Highlight/AreaHighlight+Popup - 非 PDF 降级分级：入口 supportsSourceLocate 只放行 pdf/xlsx/xls；docx 用 react-docx 预览、txt/json 纯 pre 无定位——即 docx/txt 打开抽屉只看不滚 - 图片 chunk：/documents/images/{image_id}，fetch+Authorization→blob→createObjectURL（引用计数+30s 延迟回收防内存泄漏）

对我们 P0#2 的落地映射： - 我们无 PDF 查看器需求（片段卡即目标），只需"标记→胶囊→点击滚动到 KgGraphCard 片段"——抄胶囊形态即可，不需要 react-pdf-highlighter 重设施 - Vue 迁移警示（D 轮审查补充）：①reactStringReplace 返回 React 元素数组，Vue 零等价——用 markdown-it 自定义 inline 规则把 [片段:N] 渲染为 <span data-chunk-idx="N"> + 容器级事件委托；②rehype 插件链是 react-markdown 特有，Vue 选 markdown-it 则整条链重写为 token renderer（"插件顶层定义"防重建优化不再适用）；③HoverCard 用 reka-ui 替代；④"先 DOMPurify 后 markdown"实为双重消毒（DOMPurify+rehype-sanitize），Vue 侧对应 md 渲染器内置转义，别漏第二道 - 片段卡滚动锚点设计（源码空白，须自答）：chunk 唯一键→DOM 锚点（片段卡容器 :data-chunk-idx）→scrollIntoView({block:'center'})；滚动容器归属要定（KgGraphCard 所在滚动父级）；iframe 嵌入模式下答案与片段卡若跨 iframe，需 postMessage 通知父页定位——RAGFlow 源码无此场景可抄 - 编号 off-by-one：RAGFlow [ID:0] 显示"图 1"（chunkIndex+1）；我们后端 [片段:N] 的 N 必须先对齐 sources.chunks 下标语义，否则点击错位 - 编号权威源与 rerank 交互见蓝图 P0#2
