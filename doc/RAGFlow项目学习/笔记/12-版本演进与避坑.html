12 · 版本演进与避坑

release_notes.md 42 个版本（v0.5→v0.27.2）+ FAQ 的考古结论——前人决策记录。

1. 演进时间轴（v0.20→v0.27.2，2025-08→2026-09）

版本 主题
v0.20 Agent/Workflow 统一编排+MCP 全量落地（旧 Agent 不兼容需重建）
v0.21 可编排摄取管道；GraphRAG/RAPTOR 改手动批量构建；TOC 长上下文
v0.22 5 个在线数据源同步；Flask 同步→异步；只发 slim 镜像（弃 9GB full）
v0.23 Memory 接口；Agent 组件重构+结构化输出；父子分块；GraphRAG 再加速
v0.24 Memory API；多沙箱；多 Admin；OceanBase——企业化补齐
v0.25 API 全量 RESTful 化；元数据过滤下推；性能专项（ES 延迟-50~100%）
v0.26 模型列表自动拉取；10+ 连接器爆发；聊天渠道（Discord/飞书/WhatsApp/钉钉）
v0.27 Knowledge Compilation 统一（GraphRAG/RAPTOR 弃用收编）；Agentic RAG 重构；Go 后端落地

叙事：检索/引用一次到位；GraphRAG 粗→提速→两度重构→收编；Agent 五轮重构；连接器是中后期最大投入线。

2. Breaking changes 暴露的"没想清楚"

版本 变更 官方理由
v0.14 service_config.yaml.template 取代手写 配合 .env 动态生成
v0.17.2 移除 Chat/Generate Max_tokens 截断应查模型商
v0.18 移除内置 rerank 模型 "对检索率影响极小但显著增加检索时间"（接口保留接外部）
v0.20 旧 Agent 全部不兼容 Agent/Workflow 统一重构
v0.22 弃 full 镜像 9GB 负担
v0.24 Reasoning→Thinking；ToC→PageIndex 概念重整
v0.27 GraphRAG/RAPTOR 从 UI 移除 并入 Knowledge Compilation

3. 性能轨迹

  • v0.17.2 "Accelerates knowledge graph extraction"（社区流传 8550s→608s ≈14 倍，官方 release notes 仅定性表述，数字出处为社区文章）；根因是修复图谱重复抽取+并行化
  • v0.14 词权重优化检索-50%；v0.23 GraphRAG 再加速；v0.26 社区抽取/实体消歧 checkpoint+resume（"最贵最耗时环节"）
  • v0.25.5：ES 延迟-50~100%、启动-5~9s/省 200MB（懒加载）、TTS Redis 缓存
  • 两度修内存泄漏（v0.19.1 高并发、v0.20.3 PyPDF）

4. Bug 高频区（他们疼过的地方）

  1. 解析类断层第一：docx 表格/QA 丢行/CSV 编码/Markdown 表格重复分块/Excel 图表归属/MinerU 页眉误抽
  2. Agent 组件：模板插值失效/Iteration 变量错位/会话消息串扰/引用无限增长
  3. 并发稳定性：上传挂死整服务（v0.27.0 修）/大文件解析挂死

FAQ 承认：解析比 LangChain 慢（DeepDoc 代价）、资源要求高（RAM≥16GB）、仅 ES/Infinity 满足混合检索（自研 Infinity 的立项理由）、任务队列卡死需手清 Redis、RAM 不足致解析近完成时被杀（调 MEM_LIMIT）。

5. 对我们路线的校准

必然要补（他们后来都做了）：元数据体系、评测基准（v0.11 即内置 ms_marco/miracl）、长任务断点续跑、昂贵索引操作给用户手动控制权、可观测（Langfuse 会话级）、API 安全兜底。

可跳过的弯路：内置 embedding/rerank 本地模型（终被外置取代）、知识增强独立开关形态（三度摇摆）、自研文档引擎的双引擎兼容 bug 无休止。

相似度：我们 P0-P2 路线 ≈ 其 v0.6→v0.18 路径，方向正确；引用系统需按"长期工程"预留持续投入。
