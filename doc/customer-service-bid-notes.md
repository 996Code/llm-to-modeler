**可用于技术方案的概述：** 系统采用“统一服务入口、平台运行底座、智能客服场景编排、知识证据服务、MCP 业务接口适配”的分层架构。平台提供会话与状态管理、模型服务接入、插件装配和结构化交互。智能客服根据问题识别业务场景，提取必要条件，缺失时发起追问；知识咨询通过本地知识证据服务返回带来源引用的辅助结论，业务查询通过指定数据源与固定 MCP 工具访问预定义业务接口。业务系统返回的成功、无权限、查无记录和服务异常分别处理，不将错误包装成成功数据。

**部署与实施约束：** 本项目业务查询应限定使用已审批的本地预定义接口，不开放通用问数入口，不向外部模型提供数据库账号、网络访问权限或业务 SQL 执行能力。业务数据归属校验在业务系统实施，平台侧完成身份交换、字段映射、接口白名单、审计与网络边界的专项联调验收。此段是实施约束，不表示当前代码已经具备全部强制门禁。

## 二、不同问题实际走哪条链路

### 1. 知识咨询：强检、资质与工作日

用户问题进入客服后，通过模型识别场景与提取条件；强检等场景按用途等条件选择知识库。插件调用 `retrieve_evidence` 获取片段，综合图谱、按配置开启的向量以及图谱无种子时的全文补召回，再基于片段生成结构化结论，校验结论类型与引用编号。没有有效片段时返回无法确定并建议人工确认。

不能把一般知识问答工具的全部重排、补检机制画成客服必经步骤。知识检索仍可能依赖模型完成查询意图处理；当前不是模型全部不可用时自动切换的纯检索问答。

### 2. 业务查询：检测进度与价目

场景固定数据源与工具，提取出的条件作为参数送入 `execute_controlled`。执行器检查数据源存在、启用、类型为 MCP，检查配置的工具限制及部分输入 Schema，然后通过 SDK 建立 MCP 连接、初始化并调用工具。返回先做业务信封判定，只有成功数据才归一成记录或表格。

客服不会把自然语言交给模型生成业务 SQL。平台的通用 `ask_data` 另有模型生成 SQL 的能力，必须与本项目的客服业务查询隔离；不能宣传整个仓库完全不存在模型生成 SQL。

### 3. 多系统接入

每个外部系统登记服务 `code`、URL、静态请求头与超时，发现工具后保存名称、描述和输入 Schema。客服场景绑定具体数据源与工具，支持配置场景以及从工具声明合成的自动场景。

URL 以 `/sse` 结尾使用 SSE，其他地址使用 Streamable HTTP。这是按地址选择，不是失败后自动协议协商。每次调用新建连接，用完关闭；没有连接池、OAuth 自动刷新或动态用户凭证交换。当前按裸工具名去重，跨系统同名工具存在相互遮蔽风险，不宜承诺零配置命名隔离。

## 三、走不通时的处理

| 条件 | 当前行为 | 不能混同为 |
|---|---|---|
| 必要条件缺失或格式不符 | 追问补齐；保存状态并恢复流程 | 自动猜测参数、业务办理提交 |
| 首轮问题未匹配已知场景 | 返回能力范围提示；有历史场景时可能沿用历史场景 | 所有未知问题都必定拒答 |
| 无知识片段或结论不确定 | 返回不确定并建议人工确认 | 已建立人工工单、客服坐席自动转接 |
| 数据源缺失、停用或不是 MCP | 返回前置错误，不发业务请求 | 自动换库或改走 SQL |
| 固定工具限制不符、已知非空快照中无工具、基础验参失败 | 拒绝调用并提示检查配置或刷新快照 | 完整 Schema 或审批白名单机制 |
| 注册表读取异常、工具快照为空、缺 Schema | 部分验参放行到传输层 | 全程 fail-closed 的强安全闸门 |
| 注册探测失败 | `pending`，工具快照置空 | `pending` 自动禁止后续调用 |
| 上游返回拒权或查无 | 进度、价目部分场景有专用通知；其余错误诊断 | 成功表格、平台已完成业务权限验证 |
| 上游超时、连接或凭据问题 | 如实返回错误；当前 SDK 多数传输错误统一归 retryable | 已自动重试、已准确区分所有 401 |
| 未知业务状态、返回形状不符 | 作为契约错误，不猜列名或业务结果 | 大模型自行修补业务数据 |
| 模型主端点连接、超时、408 或 5xx 失败 | 有配置时可切备用端点 | 任何错误都切备、MCP 业务 API 主备 |
| 主备模型均不可用 | 错误显式上报 | 已有自动纯检索降级 |

受控执行和 MCP SDK 本身没有自动重试循环。`retryable` 是错误分类，不是已经发生重试。声明质量门禁也不等于只读安全门禁：当前工具快照不保留 `readOnlyHint` 等注解，执行器未实施读写判定、写操作审批、幂等或事务保障。

## 四、参考需求逐场景映射

| 编号 | 参考需求 | 当前代码可证明的能力 | 投标实施边界 |
|---|---|---|---|
| 4.11 | 检测检定进度 | 固定 `query_progress` 与进度卡、拒权和查无处理 | 真实委托/证书号映射、状态枚举、身份归属需对接 |
| 4.12 | 上门预约查询 | 有模拟 `query_appointment`，按日期查询已有预约，可合成自动场景 | 不等同按委托号或报检单号查询；无创建/改约闭环 |
| 4.13 | 附件组合报价 | 模拟单器具、数量、加急估算工具 | PDF/Excel/Word/图片识别到清单再组合报价未形成；数字参数类型适配仍有缺口 |
| 4.14 | 单项收费标准 | `query_instrument` 展示型号、价格、周期、规程号等 | 演示读取预转换 JSON；24 小时同步与权威价目更新需交付 |
| 4.15 | 身份验证后费用 | 可复用固定接口执行框架 | 无真实身份验证费用查询闭环；静态请求头不等于个人身份 |
| 4.16 | 发票咨询 | 可通过配置内容或外部能力扩展 | 默认无专门发票场景；宁计量平台操作指引需配置与核验 |
| 4.17 | 检测工作日 | `turnaround` 知识证据场景 | 依赖已导入权威资产，不是实时排产或时限承诺 |
| 4.18 | 现行规程规范 | 价目工具能返回规程号，知识服务可承载文档 | 没有默认独立规程全文场景；现行有效性需资产治理 |
| 4.19 | 检定/校准周期 | 价目查询可返回 `period_months` | 不能视作依据所有规程条件自动推导的法定周期引擎 |
| 4.20 | 强检判定 | 用途追问、条件选库、三态结论及引用 | 应表述为证据辅助判定；不能等同权威法律裁定 |
| 4.21 | 主题库与接口交付物 | 平台有配置、状态和工具接入结构 | 采购人主题库清单/主键/关联/频率、接口文档、联调、压测和对账样例需另行交付 |

表格类知识演示可覆盖价目、强检目录、周期和资质，但数据来源不同：价目与周期可来自 MCP；强检与资质走知识证据；演示资产不等于采购人权威资料已接入。

## 五、模型与数据合规核查

| 条款 | 当前现状 | 响应注意事项 |
|---|---|---|
| 2.1 多家可插拔 | 有数据库主端点与可选备用端点 | 仍须提供至少两家真实供应商配置与切换验证 |
| 2.2 境内合规备案 | 供应商配置未形成地域/备案硬校验 | 需采购人同意、供应商备案证明和网络出口约束 |
| 2.3 成本控制 | token 估算与校准、RPM/TPM、进程内缓存、可选价格计费日志 | 缓存默认/配置有差异；无会话硬预算上限或完整渠道限流承诺证据 |
| 2.4 降级 | 部分故障可切备用模型；检索有向量故障保留图谱/全文的子路径容错 | 没有主备全失败后的自动纯检索问答闭环 |
| 2.5 出机构前脱敏 | 已有日志入库前脱敏；发送模型仍使用原始 messages | 不满足同等出站脱敏表述；姓名等覆盖和可逆映射需专项设计 |
| 2.6 知识注入 | 证据检索与 Prompt 注入，无需重新训练 | 实际更新延迟受导入和任务队列影响，需定义完成口径 |
| 2.7 首字 2 秒/完整 5 秒 | SSE 及调用耗时字段已存在 | 未取得真实首字、完整时延及压测证据，不可承诺已达标 |
| 2.8 全量日志 6 个月 | 会话/调用日志和 token 字段存在 | 日志可关闭或仅摘要；无完整 MCP 逐调用审计、6 个月归档策略证据 |
| 2.9/2.10 内网与白名单 | 客服固定 MCP 工具路径不生成 SQL | 需限制通用 ChatBI、补齐审批白名单、用户身份和强只读约束；网络及数据库端口须现场验收 |

管理访问还依赖部署配置：`ADMIN_TOKEN` 未配置时可开放管理接口。MCP 请求头明文保存在受控平台库中，当前不是加密凭据保险库。不能将“支持鉴权配置”写成默认已达成全部安全要求。
